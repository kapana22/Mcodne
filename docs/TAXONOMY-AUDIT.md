## 3. კრიტიკული შეფასება

### ✅ P1 — გასწორებულია ჩემი მტკიცება, არა კოდი

**ეს პუნქტი თავდაპირველად არასწორად დავწერე.** ვამტკიცებდი, რომ `finance`,
`sales`, `advokati`-ს 6 პროფილი ფილტრში არ ჩანს. გავზომე და პირიქითაა:

```
?category=law       → 5   (პირდაპირ law-ზე: 4)   ← ადვოკატი ჩანს
?category=tax       → 7   (პირდაპირ tax-ზე: 4)   ← ფინანსები ჩანს
?category=marketing → 6   (პირდაპირ: 4)           ← გაყიდვები ჩანს
```

`BROWSABLE_CATEGORY` და `foldCounts` განზრახ ითვალისწინებენ გადამისამართებას —
ბავშვი კატეგორიის ექსპერტი მშობლის ქვეშ ჩნდება და მშობლის ციფრშიც ითვლება.
კოდის კომენტარიც ამას ხსნის.

**ნამდვილი, უფრო პატარა დეფექტი:** `marketing` ფილტრში 6-ია, რელსში 5;
`business` ბაზაში 2-ია, რელსში 1. სხვაობა `COUNTABLE_EXPERT`-ია — ციფრი და
ფილტრის შედეგი ორ სხვადასხვა წესზეა აშენებული. `foldCounts`-ის საკუთარი
კომენტარი კრძალავს ამას: *„A number shown next to a sphere has to match what
tapping it returns."* ეს ერთი წესის გათანაბრებაა, არა მიგრაცია.

**დუბლიკატები რჩება — მაგრამ როგორც სახელების საკითხი.** „ადვოკატი"
პროფესიაა და არა კატეგორია; ის უკვე გადამისამართებულია და ზიანს არ აყენებს.

### 🔴 P2 (თავდაპირველი აღწერა) — 13 პროფესიას შეუძლია სამუშაო, მაგრამ ვერცერთი ვერ ყიდის

`PROFESSION_CAN`-ში 91-დან **13 პროფესია** მონიშნულია `[W]`-ით: ბუღალტერი, დეველოპერი, ფოტოგრაფი, კოპირაითერი, არქიტექტორი, ინტერიერის დიზაინერი, თარჯიმანი და სხვ.

მაგრამ თავად ფაილში წერია:

> „⚠️ WORK for an expert profession is DATA ONLY today — nothing routes on it yet"

**ეს არის მთავარი ხარვეზი ახალ იერარქიასთან.** საიტი ამბობს „ვყიდით სერვისს", ბუღალტერი მონიშნულია როგორც სამუშაოს შემსრულებელი — და **„დეკლარაციის შევსებას" მაინც ვერ ყიდის.** მას მხოლოდ „კონსულტაცია 60წთ" შეუძლია გამოაქვეყნოს.

**გასაკეთებელი:** ექსპერტის „ჩემი სერვისები" გვერდმა უნდა მისცეს დასახელებული, ფასიანი სერვისის დამატების საშუალება — ზუსტად ისე, როგორც პროვაიდერს აქვს. ეს ყველაზე დიდი ცალკეული სამუშაოა ამ სიაში და ყველაზე მაღალი ეფექტის.
